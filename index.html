FinNexus (Core)

La super-app financiera híbrida que permite a los usuarios realizar pagos con códigos QR de forma instantánea y transferir excedentes a carteras de inversión de alto rendimiento.

Justificación Arquitectónica

Punto central de orquestación. Separa lógicamente el flujo diario de pagos (que exige latencia mínima) de las inversiones (que operan en horarios de mercado y requieren validación KYC). Esto evita que los cuellos de botella del mercado afecten la rapidez en comercios.

Angular + Capacitor

Frontend SPA Híbrida

Entrega la interfaz de usuario web y nativa móvil para Android/iOS desde una única base de código. Se encarga de capturar la biometría táctil/facial y activar la cámara nativa para escanear los códigos QR.

Decisión Tecnológica (Trade-off)

¿Por qué Angular + Capacitor? Provee un framework fuertemente tipado (TypeScript) e inyección de dependencias nativa, esencial para la mantenibilidad financiera. Usar Capacitor en lugar de nativo puro nos permite un Time to Market drásticamente menor mediante código reutilizable, atacando las limitaciones de presupuesto (ROI). Además, permite separar el frontend del backend para mayor escalabilidad.

Análisis de Atributos de Calidad

Visualización de las implicaciones del Teorema CAP y trade-offs entre los módulos del sistema.

Teorema CAP: Pagos QR vs. Inversiones

Módulo Pagos QR (Base NoSQL)

Prioriza la Disponibilidad (A) y Tolerancia a Particiones (P). Si un nodo cae, el usuario debe poder pagar en la tienda (Consistencia eventual).

Módulo Inversiones (Base Relacional)

Exige Consistencia Estricta (C) y Tolerancia a Particiones (P). No se permite doble gasto; requiere transacciones ACID inmutables.

* Justificación para usar bases de datos separadas (Firestore vs PostgreSQL) en el Nivel C2 de FinNexus.

Protocolos de Comunicación (C2)

  • HTTPS / TLS 1.3 Obligatorio para asegurar cifrado financiero.
  • REST Simplifica integraciones CRUD básicas.
  • WebSockets Solo para precios de bolsa en tiempo real, evitando sobrecarga de servidor.

Arquitectura Ultra-Segura

El uso de un API Gateway centralizado permite gestionar la autenticación (JWT) y encriptación de payloads antes de tocar los microservicios core, cumpliendo el atributo primario de Seguridad.
